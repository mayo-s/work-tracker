Components

    Component gallery

    The UI elements of the Work Tracker (SPEC 5.5), each with its use and the HTML to copy. Not linked in the navigation.

    Colors

    Use the variables, never hex values. Warning colors only for real warnings; mint only for positive values. Dark mode uses the same variables with dark values; preview it here (not saved, it only changes this page).

    Theme

    Text

    Inter, regular and semibold. Muted text for secondary information such as weekday, target or notes.

    Title

    Section heading

    Body text with emphasis, a link and muted text.

    Values

    Times and durations always with num (tabular digits). Overtime and balance: negative as warning, positive in mint, zero plain.

    +1:15 -8:00 0:00 08:15–16:00

    Badges

    Short labels: day types, counts, balance. A warning badge for things that need attention.

    PTO Balance 12:30 3 to review

    Buttons

    One primary button per area (e.g. Save); everything else normal. Links that act like buttons use button class. button-small for row actions such as Edit, button-danger for deleting.

    Link as button

    Form fields

    Label above the field, an optional hint below it. Invalid fields get aria-invalid="true" and a warning message below. Clock times are text fields (HH:MM), not type="time", which some systems show in 12-hour format.

    End is before start

    empty: legal minimum

    Tables

    Durations right-aligned with td class="num"; clock times stay left-aligned with a span class="num". Row states: is-today, is-warning (e.g. a past work day without entries), is-weekend.

    Task entries of a day: duration (plain; 0:00 as warning), ticket or activity type, service, text, badges for coding, review flags and changes; History and Edit on the right (dimmed until hover). The history lists each change, oldest first.

    Dialog

    A question before saving, e.g. minutes instead of hours, the quarter hours around a time, or days off on days that hold times. ask() in dialog.ts builds it and opens it modally with showModal(): the focus stays inside, Escape cancels, the main choice is primary, Cancel comes last. Use it only when a decision is needed; errors belong next to the field.
